الـ Cascade: لما قاعدتين يتخانقوا مين يكسب؟

الـ «C» في CSS = Cascading. على أي عنصر ممكن 10 قواعد تحاول تحدد نفس الخاصية. المتصفح عنده خوارزمية ثابتة بتقرر مين يكسب. أغلب «الـ CSS مش شغّال!» اللي بتقابلها كمطوّر سببها إنك مش فاهم الخوارزمية دي — وكمهاجم، فهمها بيقولك الـ CSS اللي حقنته هيغلب ولا لأ.

ترتيب الحكم (Cascade Level 5)

1

Origin + Importance

للقواعد العادية: CSS المتصفح < CSS المستخدم < CSS الموقع. ومع !important الترتيب بيتعكس (الـ !important بتاع المستخدم بيغلب بتاع الموقع — عشان الـ accessibility). وأي !important بيغلب أي قاعدة عادية.

2

Element-attached styles

الـ style="" attribute بيغلب أي قاعدة من stylesheet (من نفس المستوى) مهما كانت الـ specificity.

3

Layers (@layer)

الطبقة اللي اتعرّفت أخيرًا بتكسب، والـ CSS اللي برا أي layer بيغلب كل الـ layers (للقواعد العادية).

4

Specificity

الأوزن selector يكسب: (A ids، B classes/attributes/pseudo-classes، C types/pseudo-elements) وبتتقارن من الشمال: A الأول.

5

Order of appearance

لو كل اللي فات اتعادل: اللي مكتوب أخيرًا يكسب.

قواعد عملية للمطوّر

(1) استخدم classes تقريبًا لكل حاجة، وابعد عن الـ ids في الـ CSS. (2) !important = علامة إن فيه حرب specificity — استخدمه بس في utilities أو لتجاوز CSS خارجي. (3) :where() بيدّي specificity صفر، ممتاز للـ resets والمكتبات عشان المستخدم يعدّلها بسهولة. (4) منهجيات زي BEM (.card__title--active) بتخلي كل الـ selectors class واحدة فالـ specificity مسطّحة ومتوقعة.

الـ Layers: نظّم الحرب من الأول

/* declare the order once: later layers win */ @layer reset, base, components, utilities; @layer components { .card .title { color: navy; } /* (0,2,0) */ } @layer utilities { .text-red { color: crimson; } /* (0,1,0) — still wins: its layer is later */ } /* unlayered CSS beats every layer (for normal declarations) */

الوراثة (Inheritance)

خصائص النص (color، font-*، line-height، text-align، direction، visibility، cursor…) بتتورث من الأب للأبناء. خصائص الصندوق (margin، padding، border، background، width، display…) مش بتتورث. وتقدر تتحكم صراحة:

القيمةالمعنى
inheritخد قيمة الأب
initialالقيمة الابتدائية في الـ spec (مثلًا display: inline)
unsetinherit لو الخاصية بتتورث، وإلا initial
revertارجع لقيمة المتصفح (user-agent) أو المستخدم
revert-layerارجع لقيمة الـ layer اللي قبلي

هل الـ CSS اللي حقنته هيغلب؟

لو حقنت قيمة جوه style="" attribute: بتغلب كل قواعد الـ stylesheet العادية (element-attached). لو حقنت <style>: لازم تغلب بالـ specificity أو الترتيب أو !important — والـ !important بتاعك بيغلب الـ !important بتاع الموقع لو specificity أعلى أو جاي بعده. ده بيفرق جدًا في هجمات UI redressing: إظهار عنصر مخفي (display: block !important)، أو إخفاء تحذير أمني، أو تغطية الصفحة بطبقة مزيفة.
