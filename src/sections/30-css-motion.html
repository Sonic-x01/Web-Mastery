الحركة: transform وtransition وanimation

الحركة الصغيرة الصح بتخلّي الواجهة «حيّة» وبتفهّم المستخدم إيه اللي حصل (زرار اتضغط، قايمة فتحت). في الدرس ده هنحرّك العناصر من غير ما نبوّظ الـ layout، ونفهم ليه بعض الخصائص بتهنّج الصفحة وبعضها ناعم على الـ GPU. وفي الآخر: إزاي events الأنيميشن بقت vector مشهور للـ XSS بيعدّي من فلاتر كتير.

transform: حرّك من غير ما تأثر على الجيران

transform بيغيّر شكل رسم العنصر بس — مكانه في الـ layout زي ما هو، فالعناصر اللي جنبه مش بتتحرك.

الدالةبتعمل
translate(20px, -10px)تحريك (يمين 20 وفوق 10). translate(-50%, -50%) = نسبة من حجم العنصر نفسه
rotate(45deg)لف مع عقارب الساعة (turn كمان: 0.5turn = 180°)
scale(1.2) / scale(2, 1)تكبير/تصغير (من غير ما الـ layout يتغير)
skew(10deg)ميل

الـ transform-origin (الافتراضي center) هو النقطة اللي اللف والتكبير بيحصلوا حواليها. والترتيب بيفرق: translateX(100px) rotate(90deg) غير rotate(90deg) translateX(100px)، لأن كل دالة بتشتغل في الإحداثيات اللي سابتها اللي قبلها (في التانية الـ X نفسه لفّ فالعنصر هينزل لتحت). والحديث: الخصائص المنفصلة translate: 10px 0; rotate: 15deg; scale: 1.1;.

transition: من حالة لحالة

.btn { background: #2563eb; transition: transform .2s ease-out, background-color .2s; /* what · how long · curve */ } .btn:hover { transform: translateY(-3px); background: #1d4ed8; } .btn:active { transform: translateY(0) scale(.97); } .btn:focus-visible { outline: 3px solid #93c5fd; outline-offset: 2px; }

الشكل الكامل: transition: property duration timing-function delay. ابعد عن transition: all — بيحرّك حاجات مش قاصدها وبيبطّأ. ومش كل خاصية بتتحرّك: display مثلًا «discrete» (يا ده يا ده)، عشان كده الإظهار الناعم بيتعمل بـ opacity + visibility.

Timing functions

(المثال ده بيحرّك margin-left عشان يبقى بسيط في العرض — تحت هتعرف ليه ده مش الأفضل في الحقيقة.)

@keyframes وanimation

@keyframes spin { to { transform: rotate(360deg); } } /* from = current style */ @keyframes pulse { 0%, 100% { opacity: 1; } 50% { opacity: .4; } } .spinner { animation: spin 1s linear infinite; } /* name | duration | timing | delay | iteration-count | direction | fill-mode */ .toast { animation: pulse .6s ease-in 0.5s 3 alternate both; }
الخاصيةالقيم المهمة
animation-iteration-count3، infinite
animation-directionnormal، reverse، alternate (رايح جاي)
animation-fill-modeforwards = يفضل على آخر frame بعد ما يخلص. backwards = ياخد أول frame أثناء الـ delay. both
animation-play-statepaused / running

من غير forwards، أول ما الأنيميشن يخلص العنصر بيرجع لـ style بتاعه الأصلي فجأة — غلطة مشهورة.

الأداء: Layout → Paint → Composite

كل frame المتصفح ممكن يعدّي على 4 مراحل: يحسب الـ Style، يعمل Layout (مقاسات وأماكن)، Paint (يرسم البكسلات)، وComposite (يركّب الطبقات على الـ GPU). لو حرّكت width أو left أو margin: كل frame فيه layout جديد — وغالبًا للصفحة كلها. ده اللي بيعمل «jank» (تقطيع) خصوصًا على الموبايل. الألوان والظلال: مفيش layout، بس فيه paint كل frame. مقبول للحاجات الصغيرة. transform وopacity: الـ composite بس. عشان كده القاعدة الذهبية: حرّك بـ transform وopacity. (will-change: transform بيجهّز طبقة مقدمًا — استخدمه بحذر لأنه بياكل memory.) شوف بنفسك: DevTools ← Performance، أو Rendering ← Paint flashing.

احترم prefers-reduced-motion

ناس كتير عندهم دوخة أو صداع أو حساسية من الحركة. لما المستخدم يطلب كده من نظامه، قلّل الحركة لأقل حاجة:

@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: .01ms !important; animation-iteration-count: 1 !important; transition-duration: .01ms !important; scroll-behavior: auto !important; } }
🧑‍💻
Developer

الحركة لازم يكون ليها سبب: feedback (زرار اتضغط)، علاقة (القايمة طلعت من الزرار ده)، أو انتباه لحاجة مهمة. مدة الـ UI العادية 150–300ms. ولو محتاج تحكم من JS: element.animate(keyframes, options) (الـ Web Animations API) وelement.getAnimations() — هنشوفهم في جزء الـ JavaScript.

🎯 Events الأنيميشن: XSS من غير أي click

كل CSS animation بتطلق events على العنصر: animationstart، animationiteration، animationend. والـ transitions: transitionrun، transitionstart، transitionend. وليها attributes: onanimationstart، onanimationend، ontransitionend… — يعني event handler بيشتغل لوحده من غير تفاعل، زي onerror بالظبط.

فلاتر كتير بتعمل blocklist لـ onerror وonload وonclick وonmouseover بس. payload زي ده بيعدّي:

<b style="animation-name:x" onanimationstart="alert(document.domain)">

ولو مش قادر تحقن <style> عشان تعرّف @keyframes، استخدم keyframes موجودة أصلًا في الموقع: الـ frameworks بتعرّف أسماء معروفة (Bootstrap مثلًا: spinner-border وprogress-bar-stripes). افتح DevTools ← Sources أو دوّر على @keyframes في ملفات الـ CSS. والحل الصح عند الـ developer: allowlist + output encoding + CSP — مش blocklist لأسماء events (القايمة أطول من أي blocklist).

🦠
Malware / Phishing

الأنيميشن بيُستخدم في الـ phishing والـ scareware: «progress bar» مزيف لـ «فحص فيروسات»، أو spinner بيوهم بإن الصفحة بتتحقق من حاجة. وفي الـ clickjacking (الدرس 11) ممكن عنصر يتحرك في اللحظة المناسبة تحت الماوس عشان يخطف الضغطة.

قيمة document.querySelector(".box").offsetWidth كام؟ (offsetWidth = عرض الـ layout: content + padding + border.)

الأنيميشن ده بيخلص نهائيًا بعد كام ثانية من تحميل الصفحة؟

 .toast { animation: pulse 0.5s ease-in 1s 3 alternate; } الترتيب: name · duration · timing · delay · iteration-count · direction. أول رقم وقت = duration، والتاني = delay. delay ثانية + 3 مرات × 0.5 = 2.5 ثانية. (الـ alternate بيغيّر الاتجاه بس مش المدة.)
