البروفايل بتاعك… بقى شكله احترافي

أساسي▼

خد بروفايل مشروع 01 (الجزء الأول) واكتبله ملف style.css منفصل من الصفر. الدروس: 19–24، 28، 30، 31.

  1. Reset + tokens: reset صغير (الدرس 30)، وعلى :root متغيرات للألوان والمسافات والـ radius والخطوط.
  2. Typography: font-family بـ fallbacks، line-height 1.6، عرض السطر max-width: 70ch، وعناوين بـ clamp().
  3. Layout: الـ header بـ Flexbox (اللوجو يمين والـ nav شمال)، وقسم المهارات Grid بـ auto-fit.
  4. Dark mode: prefers-color-scheme بيغيّر المتغيرات بس، وcolor-scheme: light dark.
  5. Accessibility: :focus-visible واضح، skip link بيظهر مع الـ focus، وكل الألوان ≥ 4.5:1 (اختبرها بالـ Contrast Checker).
  6. Stretch: زرار يبدّل الثيم يدويًا (هتعمله بـ JS في الجزء الجاي) — جهّز له [data-theme="dark"] من دلوقتي.
التسليم: index.html + style.css من غير أي style="" inline، Lighthouse Accessibility ≥ 95، ومفيش scroll أفقي من 320px لـ 1920px.

Landing page متحركة… وسريعة

متوسط▼

طوّر الـ landing page بتاعة مشروع 09 بحركة محترمة من غير ما تخسر الأداء. الدروس: 24، 25، 29، 31.

  1. Hero: عنوان بـ clamp()، خلفية gradient، وelement واحد بيتحرك بـ @keyframes (transform/opacity بس).
  2. Micro-interactions: الأزرار والكروت بـ transitions (150–300ms) على خصائص محددة — مفيش transition: all.
  3. Reduced motion: prefers-reduced-motion: reduce يوقّف كل الحركة غير الضرورية.
  4. الخطوط: خط واحد بـ woff2 وfont-display: swap وpreload، أو system fonts.
  5. الأداء: الصور بـ width/height (عشان CLS = 0)، critical CSS صغير، وراجع الـ Coverage tab.
التسليم: Lighthouse Performance ≥ 90 وCLS = 0، وتسجيل Performance من DevTools مفيهوش «Layout» أثناء الأنيميشن.

Accessibility audit: لاقي المشاكل وصلّحها

متقدم▼

زي الـ pentest بالظبط بس للـ accessibility: تفحص، توثّق بـ severity، تصلّح، وتعيد الاختبار. الدروس: 23، 28، 31.

  1. الهدف: صفحة الـ login بتاعة مشروع 03 (أو أي موقع قديم عندك).
  2. الفحص اليدوي: الصفحة كلها بالكيبورد بس، zoom 200%، عرض 320px، وdark mode، وWindows High Contrast لو متاح.
  3. الفحص الأوتوماتيك: Lighthouse وأداة زي axe DevTools — واعرف إن الأدوات بتمسك حوالي ثلث المشاكل بس.
  4. التقرير: جدول (المشكلة، المعيار في WCAG، المكان، الـ severity، الإصلاح) — نفس قالب تقرير الـ recon.
  5. الإصلاح وإعادة الاختبار: commit لكل مشكلة، وسكرين before/after.
التسليم: a11y-report.html (ويتطبع PDF نضيف) + النسخة المصلّحة، ومفيش ولا مشكلة contrast أو focus متبقية.

🎯 Recon من ملفات الـ CSS

متقدم▼

ملفات الـ CSS بتتنسي في الـ recon، مع إنها بتكشف نسخ مكتبات، مسارات، وhosts داخلية. ده جزء من app.min.css على megacorp.example (هدف تخيلي في نطاق اختبار مسموح). الدروس: 15، 30، 31.

  1. نزّل كل ملفات الـ CSS (DevTools ← Sources أو Network ← filter CSS) وطلّع الـ banner comments.
  2. طلّع كل الـ url(…) والـ hosts، وكل الـ attribute selectors اللي فيها href أو أسماء زي admin/beta/debug/internal.
  3. جرّب الـ source maps (.css.map)، وطابق النسخ القديمة مع الـ CVEs (Retire.js، NVD).
  4. اكتب كل نتيجة بـ severity مبدئية — الـ «path مخفي» لوحده Informational، لحد ما تختبر الـ endpoint وتثبت مشكلة صلاحيات.

إيه الـ host اللي اسمه بيقول إنه داخلي (ويستاهل تضيفه لقايمة الـ subdomains)؟

 cdn-int.megacorp.example — الـ int غالبًا internal. ضيفه للـ recon (DNS، الـ certificate، هل متاح من برا؟).

نسخة أنهي مكتبة UI ممكن يكون ليها XSS معروفة؟ اكتب رقم النسخة.

 Bootstrap 3.3.7: النسخ قبل 3.4.1 ليها CVEs معروفة (XSS في data-* attributes بتاعة tooltip وcollapse). اختبرها لو الموقع بيستخدم الـ JS بتاع Bootstrap مع input من المستخدم.

الملف ده موجود على https://megacorp.example/assets/css/app.min.css. إيه الـ path اللي هتجربه عشان الـ source map؟

 الـ sourceMappingURL بيتحسب relative لملف الـ CSS ⇒ /assets/css/app.min.css.map. لو رجع 200 هتشوف ملفات الـ SCSS الأصلية بمساراتها وتعليقاتها.
التسليم: قسم «CSS recon» في تقرير الـ recon بتاعك (مشروع 04)، فيه كل host وpath ونسخة لقيتها ومصدرها.

🏁 Capstone: لوحة findings كاملة (بتتصحح أوتوماتيك)

الـ HTML جاهز — اكتب الـ CSS كله. الاختبارات بتشيك على أهم قواعد الجزء التاني:

  • على :root: --accent و--bg و--fg، وجوه @media (prefers-color-scheme: dark) قاعدة :root بتغيّر --bg و--fg.
  • .grid: display: grid بـ repeat(auto-fit, minmax(220px, 1fr)) (أو auto-fill) وgap.
  • .card: الـ background من متغير (var(…))، وtransition على transform (مش all)، و.card:hover بـ translateY(…).
  • :focus-visible بـ outline عرضه 2px أو أكتر.
  • @media (prefers-reduced-motion: reduce) بيلغي الـ transition أو الـ transform بتاع الكروت.
  • .badge.critical: تباين النص مع خلفيته ≥ 4.5:1.
  • الصور: max-width: 100%، و@media print يخفي .toolbar.
  • ممنوع !important وممنوع أي id في الـ selectors.

خلصت الجزء التاني؟

دلوقتي تقدر تبني أي واجهة: layout بأي شكل، responsive، accessible، ومتحركة باحترام. الجزء الجاي JavaScript: اللغة نفسها، الـ DOM والـ events، الـ fetch والـ APIs، Node.js، وكمان قراية وفك الـ JavaScript المتلخبط (obfuscated) اللي بتلاقيه في الـ malware وصفحات الـ phishing. وبعده جزء الـ Web Security.
