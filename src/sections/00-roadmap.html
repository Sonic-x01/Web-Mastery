ليه الويب؟ ومن زاويتين: المطوّر والـ Pentester

أي web application — بنك، متجر، لوحة admin، حتى تطبيقات الـ desktop المبنية بـ Electron — بتوصل للمستخدم في الآخر على شكل HTML وCSS وJavaScript بيشغّلهم المتصفح. الكورس ده هيخليك مطوّر ويب محترف يبني مواقع وبرامج حقيقية — وفي نفس الوقت Pentester بيشوف حاجات الناس مش شايفاها: input بيتحط في مكان غلط، فورم بتبعت أكتر من اللي باين، comment نسيه المطوّر، أو صفحة phishing بتبني ملف malware جوه المتصفح نفسه.

👨‍💻 كمطوّر تطوير الويب والبرمجيات

🧱

تبني أي واجهة

مواقع، dashboards، صفحات هبوط، تطبيقات ويب كاملة — بـ HTML نضيف وsemantic، CSS بيعمل أي layout، وJavaScript بيكلم APIs.

⚙️

أساس أي software حديث

نفس الـ HTML/CSS/JS بيبني تطبيقات desktop (Electron)، وموبايل (WebViews وReact Native)، وextensions، وأدوات داخلية. والـ JavaScript نفسها بتشتغل backend بـ Node.js.

🏆

شغل باحتراف

Accessibility، أداء، SEO، تنظيم مشروع، Git، نشر — والكود الآمن من الأول: المطوّر اللي فاهم الهجمات بيكتب كود محدش يقدر يكسره بسهولة.

🎯 كـ Pentester الأمن وتحليل الـ Malware

🎯

أكبر سطح هجوم

أغلب الـ targets في الـ pentest والـ bug bounty هي web apps. كل صفحة، كل فورم، كل parameter في الـ URL هو باب محتمل — والـ HTML هو الخريطة بتاعة الأبواب دي.

💉

الثغرات = فهم المتصفح

XSS وHTML injection وCSRF وclickjacking مش «payloads بتتحفظ». دي نتيجة مباشرة لطريقة الـ parsing والـ encoding والـ origins. اللي فاهم القواعد بيكتب الـ payload بنفسه لأي فلتر.

🔍

الـ Recon بيبدأ من الـ source

comments منسية، hidden inputs، endpoints مستخبية في ملفات JS، API keys، أرقام إصدارات… كل ده بيتقري من الـ source قبل ما تبعت request واحد «هجومي».

🦠

الـ Malware بيتكلم HTML

HTML smuggling، مرفقات phishing بامتداد .html و.svg، ملفات .hta، وJavaScript متشوّش (obfuscated). محلل الـ malware لازم يقراهم ويفكّهم من غير ما يشغّلهم على جهازه.

🛠️

هتكتب PoCs وأدوات

CSRF PoC، صفحة clickjacking، تقرير فيه proof بيشتغل، bookmarklet، وscripts بـ Node.js تأتمت شغلك. ده كله HTML وCSS وJS.

🧠

أساس لكل اللي جاي

Burp Suite، اختبار الـ APIs، الـ browser exploitation، تحليل تطبيقات Electron… كلها بتفترض إنك فاهم الويب من جوه. الكورس ده هو الأساس ده.

إزاي تذاكر الكورس ده صح متقفزش

01

اقرا الفكرة

كل درس بيبدأ بالـ «ليه» قبل الـ «إزاي». لو فهمت السبب، الـ syntax هيتحفظ لوحده.

02

شغّل المثال وغيّر فيه

كل مثال عليه ▶ شغّل. متكتفيش بالتشغيل: غيّر قيمة، امسح tag، اكسر الكود — وشوف المتصفح عمل إيه. الـ 🌳 DOM بيوريك المتصفح «فهم» إيه.

03

جاوب الأسئلة

الأسئلة مصممة عشان تمسك الغلطات الشائعة. لو غلطت، اقرا الشرح — هو جزء من الدرس.

04

حل المعامل بإيدك

كل معمل بيتصحح أوتوماتيك باختبارات. اكتب الكود بنفسك؛ زرار الحل موجود بس للمراجعة بعد ما تحاول.

05

مهام التحليل والـ XSS Range

هنا بتلبس قبعة الـ pentester: تقرا source وتطلّع منه معلومة، أو تكسر صفحة ضعيفة جوه sandbox.

06

المشاريع

آخر كل جزء فيه مشاريع بتجمّع كل حاجة. دي اللي بتحوّل المعلومة لمهارة.

أدواتك جوه الصفحة كله شغّال offline في متصفحك

▶

الأمثلة الحية

كل مثال بيتعرض في «متصفح صغير» تحته. الضغط على لينك أو إرسال فورم مبيسيبش الصفحة؛ بدل كده بيتسجل تحت المعاينة: رايح فين، والـ HTTP request بالظبط اللي كان هيتبعت.

🧪

المعمل الحر (Playground)

من الزرار 🧪 المعمل فوق: محرر لـ HTML وCSS وJS، معاينة لحظية، شجرة الـ DOM الحية، Console، وتاب Requests لكل link وform. تقدر تغيّر «عنوان الصفحة» عشان تجرّب الـ relative URLs.

✔

معامل بتتصحح

مطلوب منك تبني حاجة؛ زرار تحقق بيشغّل اختبارات على الـ DOM بتاعك ويقولك إيه اللي ناقص بالظبط.

🏴

XSS Range ومهام التحليل

صفحات «ضعيفة» بكود سيرفر مكشوف (white-box) بتكسرها جوه sandboxed iframe، ومهام تقرا فيها source أو sample وتطلّع الإجابة.

جرّب دلوقتي: المثال ده صفحة login صغيرة. دوس Forgot password?، وبعدين اكتب أي username وpassword ودوس Login — وبص تحت المعاينة.

لاحظ أول حاجة «Pentester-ish»

الفورم بعتت csrf_token=a91f3c مع إن مفيش خانة باينة اسمها كده — ده input type="hidden". المستخدم مش شايفه، بس أنت شايفه في الـ source وفي الـ request، وتقدر تغيّره. القاعدة الذهبية: أي حاجة في المتصفح تحت سيطرة المستخدم.

الأداةهتستخدمها في إيه
Chrome / Firefox + DevTools (F12)Elements (الـ DOM الحي)، Console، Network (كل request وresponse)، Sources، Application (cookies وstorage). أهم أداة في الكورس كله.

⚖️
الأخلاقيات والقانون — اقراها بجد

كل الهجمات في الكورس بتتعمل جوه sandbox في الصفحة دي، أو على أنظمة إنت مالكها، أو في برامج bug bounty وscope مكتوب ومصرّح بيه. تجربة payload على موقع حد من غير إذن مكتوب = جريمة — في مصر مثلًا قانون مكافحة جرائم تقنية المعلومات رقم 175 لسنة 2018 بيجرّم الدخول غير المصرّح بيه للأنظمة والاعتداء على سلامة البيانات، وتقريبًا كل دولة عندها قانون مشابه.

للتدريب القانوني بعد الكورس: PortSwigger Web Security Academy، وHackTheBox، وTryHackMe، وOWASP Juice Shop على جهازك.

📌
اصطلاحات الكورس

الأكواد والتعليقات وأسماء المتغيرات بالإنجليزي (زي الشغل الحقيقي)، والشرح بالعربي. المرجع الرسمي هو HTML Living Standard من WHATWG، وMDN للتوثيق العملي. الـ callouts: 👨‍💻 زاوية المطوّر، 🎯 زاوية الـ pentester، 🦠 الـ malware، 🛡️ الدفاع، 📜 تفصيلة من الـ spec.

✏️ قبل ما تبدأ

في مثال الـ login فوق، مين بيقرر القيمة اللي هتتبعت في `csrf_token`؟ السيرفر بس، والمستخدم ميقدرش يغيّرها لأنها hidden المتصفح بيولّدها لوحده المستخدم يقدر يغيّرها: من DevTools أو بـ proxy زي Burp قبل ما الـ request يوصل مفيش حد يقدر يغيّرها لأن الصفحة HTTPS بالظبط. `hidden` معناها «مش معروضة» بس، مش «محمية». أي حاجة بتتبعت من المتصفح تحت سيطرة اللي قاعد عليه — والسيرفر لازم يتحقق منها. `hidden` بتخفي العرض بس. الـ HTML كله عند المستخدم، والـ request بيتبني على جهازه، فيقدر يعدّل أي قيمة. والـ HTTPS بيحمي الـ request من اللي في النص، مش من صاحب المتصفح نفسه. إيه أكتر وصف دقيق للـ XSS والـ HTML injection في الكورس ده؟ قايمة payloads لازم تتحفظ نتيجة لقواعد الـ parsing والـ encoding في المتصفح: لو فهمت القواعد تقدر تبني الـ payload المناسب لأي context مشاكل في السيرفر بس ومالهاش علاقة بالمتصفح حاجة اتصلّحت في المتصفحات الحديثة ومبقتش موجودة ده بالظبط منهج الكورس: هنفهم الـ tokenizer والـ contexts والـ decoding order، والـ payloads هتطلع منطقية. الـ payloads المحفوظة بتقع قدام أول فلتر مختلف. الثغرة بتحصل لما بيانات بتتحط في الصفحة في مكان المتصفح بيفسّرها فيه ككود — ودي قواعد في المتصفح لازم تفهمها، ولسه موجودة في تطبيقات كتير جدًا. جالك مرفق إيميل اسمه `invoice.html` من مصدر مشبوه وعايز تحلله. أنسب أول خطوة؟ تفتحه في Chrome على جهازك عشان تشوف بيعمل إيه تبعته لزميلك يفتحه تمسحه من غير ما تبص عليه تفتحه كـ نص في editor جوه VM معزولة، وتقرا الكود قبل أي تشغيل صح. التحليل الـ static الأول: تقرا الكود كنص، وتفك أي encoding، وتطلّع الـ IOCs. لو محتاج تشغيل، يبقى في VM معزولة أو sandbox زي اللي في الكورس. فتح ملف HTML مشبوه في المتصفح = تشغيل الـ JavaScript اللي فيه على جهازك. التحليل بيبدأ static: تقراه كنص في VM معزولة. (المسح من غير تحليل بيضيّع IOCs مهمة للفريق.)
