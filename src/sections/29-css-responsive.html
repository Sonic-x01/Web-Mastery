الـ Responsive Design: صفحة واحدة لكل الشاشات

أكتر من نص زيارات الويب من الموبايل. الموقع الاحترافي بيتظبط لوحده من شاشة 360px لشاشة 4K، وبيحترم تفضيلات المستخدم (dark mode، تقليل الحركة). في الدرس ده: mobile-first، الـ media queries، الـ container queries، والأحجام «السايلة». وكمان: إزاي نفس الـ media queries دي ممكن تبصم المستخدم (fingerprinting) من غير ولا سطر JavaScript.

Mobile-first

اكتب الـ CSS الأساسي للموبايل (عمود واحد، عناصر بعرض كامل)، وبعدين زوّد تعديلات للشاشات الأكبر بـ min-width. ده بيطلع CSS أبسط، والموبايل (الأضعف) بيحمّل أقل. وابدأ دايمًا بـ <meta name="viewport" content="width=device-width, initial-scale=1"> (الدرس 10).

/* base = phones */ .cards { display: grid; grid-template-columns: 1fr; gap: 12px; } img { max-width: 100%; height: auto; } /* images never overflow */ /* tablets and up */ @media (min-width: 600px) { .cards { grid-template-columns: repeat(2, 1fr); } } /* desktops — modern range syntax */ @media (width >= 1024px) { .cards { grid-template-columns: repeat(4, 1fr); } }

الـ breakpoints تتحدد حسب المحتوى (امتى التصميم بيبدأ يبوظ؟) مش حسب أجهزة معينة. جرّب في DevTools: Ctrl+Shift+M (Device Mode) وصغّر وكبّر.

الـ --bg وvar(--bg) اسمها custom properties (متغيرات CSS): بتعرّف الألوان مرة، وتغيّر قيمها جوه media query واحدة فالصفحة كلها تتقلب dark (تفاصيلها في الدرس 30). وcolor-scheme: light dark بيقول للمتصفح يلوّن الـ form controls والـ scrollbars بما يناسب الوضع.

أحجام سايلة: clamp وmin وmax

clamp(MIN, PREFERRED, MAX) = القيمة المفضّلة، بس مش أقل من MIN ولا أكتر من MAX. أشهر استخدام: عنوان بيكبر مع الشاشة بحدود: font-size: clamp(1.5rem, 4vw + 0.5rem, 3rem). وكمان width: min(90%, 700px) = سطر واحد بدل max-width + width.

Container queries: الـ component يظبط نفسه

الـ media query بتسأل عن عرض الشاشة، بس الكارت نفسه ممكن يبقى في sidebar ضيق على شاشة كبيرة. الـ container queries بتسأل عن عرض الأب:

🎯 الـ media queries كأداة tracking

/* no JavaScript needed — works even where scripts are blocked (some mail clients) */ @media (prefers-color-scheme: dark) { body { background-image: url("https://t.example/fp?dark=1"); } } @media (max-width: 480px) { html { background-image: url("https://t.example/fp?phone=1"); } } @media (pointer: coarse) { main { background-image: url("https://t.example/fp?touch=1"); } } @media (min-resolution: 2dppx) { header { background-image: url("https://t.example/fp?retina=1"); } }

كل query بتتحقق = request بيقول للسيرفر معلومة عن جهازك. ده نوع من CSS fingerprinting. ومن الناحية التانية، صفحات الـ phishing الحديثة «mobile-first» برضه: بتبان native جدًا على الموبايل (اللي فيه شريط العنوان صغير ومش واضح)، وبعضها بيعرض محتوى بريء للـ desktop/الـ scanners.

✏️ تمارين الدرس 28

«Mobile-first» معناها إيه في الكود؟ تعمل موقعين منفصلين الـ CSS الأساسي للشاشات الصغيرة، والتعديلات للأكبر جوه `@media (min-width: …)` تستخدم `max-width` في كل الـ queries تمنع الموقع على الـ desktop البداية من الأبسط والتوسع للأكبر = CSS أقل وأوضح. Mobile-first = الأساس للموبايل، والـ media queries بـ min-width بتضيف للشاشات الأكبر. `font-size: clamp(16px, 5vw, 40px)` على شاشة عرضها 1000px. الحجم؟ 50px 16px 5px 40px 5vw = 50px، بس الحد الأقصى 40px. 5% من 1000 = 50، و`clamp` بيقصها عند الـ MAX = 40. كارت بيتحط في sidebar (ضيق) وفي المحتوى الرئيسي (واسع) في نفس الصفحة. عايز شكله يتغير حسب المكان. تستخدم؟ Container queries (`container-type` على الأب + `@container`) Media queries JavaScript `!important` الـ media query مبتعرفش غير عرض الشاشة. الـ container query بتعرف عرض المكان الفعلي. المشكلة إن عرض الشاشة واحد في الحالتين — محتاج تسأل عن عرض الأب: container queries. إيميل فيه CSS: `@media (prefers-color-scheme: dark) { body { background: url(https://t.example/?d=1) } }`. لما يتفتح على جهاز dark mode وبرنامج الإيميل بيعرض الصور: مش هيحصل حاجة لأن مفيش JavaScript الإيميل هيتقفل request بيروح لـ t.example يقول إن الجهاز dark mode — fingerprinting من غير JS هيتعرض أبيض الـ CSS بيطلق requests حسب حالة الجهاز. عشان كده برامج الإيميل بتعمل proxy للصور أو بتحجبها. الـ CSS لوحده يقدر يطلب URLs حسب الشروط — من غير JavaScript.
