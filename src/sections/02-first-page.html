أول صفحة: الهيكل والـ Syntax

HTML = HyperText Markup Language: لغة توصيف مش لغة برمجة. مفيهاش متغيرات ولا loops؛ فيها «علامات» (tags) بتقول للمتصفح «ده عنوان، ده لينك، دي فورم». في الدرس ده هتبني أول صفحة صح 100%، وهتعرف القواعد اللي المتصفح بيقرا بيها — والحاجات اللي بيسامح فيها (وده بالظبط اللي المهاجم بيستغله).

السطروظيفته
<!DOCTYPE html>مش tag؛ ده إعلان بيقول للمتصفح «اشتغل بـ standards mode». لازم يبقى أول حاجة في الملف. لاحظ الـ badge في المعاينة: standards.
<html lang="en">الـ root element — كل حاجة جواه. الـ lang بيقول لغة المحتوى (لقارئات الشاشة والترجمة والخطوط). للعربي: lang="ar" dir="rtl".
<head>معلومات عن الصفحة مش بتتعرض: الـ encoding، العنوان، الـ CSS، الـ scripts، الـ meta tags.
<meta charset="UTF-8">الـ bytes دي تتقري إزاي. لازم يبقى في أول 1024 byte من الملف. من غيره ممكن العربي يطلع «Ø§Ù„…» (mojibake) — والأخطر إن اختلاف الـ encoding ممكن يكسر الحمايات (الدرس 14).
<meta name="viewport" …>عشان الموبايل يعرض الصفحة بعرضه الحقيقي بدل ما يصغّر صفحة desktop.
<title>اسم الـ tab والـ bookmark ونتيجة البحث. إجباري في المستند الصحيح.
<body>كل اللي بيتعرض للمستخدم.

الـ DOCTYPE وquirks mode

زمان قبل المعايير، كل متصفح كان بيرسم الصفحات بطريقته. لما المعايير جت، المتصفحات احتفظت بالسلوك القديم عشان المواقع القديمة متبوظش: لو الصفحة مفيهاش DOCTYPE، المتصفح بيدخل quirks mode ويقلّد سلوك متصفحات التسعينات في الـ CSS والـ layout. شغّل المثال وبص على الـ badge:

No doctype

This page has no DOCTYPE.
💡
القاعدة

أول سطر في أي صفحة تكتبها: <!DOCTYPE html>. الحروف مش فارقة (<!doctype html> نفس الحاجة)، والـ DOCTYPEs الطويلة بتاعة HTML 4 وXHTML ملهاش لازمة في أي مشروع جديد. 🎯 لما تلاقي موقع شغّال quirks mode، ده غالبًا كود قديم — ودي إشارة إن باقي الـ stack قديم برضه.

الـ Nesting: الصفحة شجرة

الـ elements بتتداخل جوه بعض، والنتيجة شجرة: html هو الجذر، وأولاده head وbody، وهكذا. المصطلحات اللي هتسمعها طول الوقت: parent (الأب)، child (ابن مباشر)، sibling (أخ — نفس الأب)، descendant (أي حد تحته)، ancestor (أي حد فوقه). القاعدة الذهبية: اللي يتفتح آخر يتقفل الأول.

<p>This is <b>very <i>important</i></b>.</p>
❌ غلط (misnested)
<p>This is <b>very <i>important</b></i>.</p>

المتصفح مش هيوقف — هيصلّحها بخوارزمية اسمها adoption agency وممكن ينتج DOM مختلف عن اللي في دماغك (الدرس 13).

الـ Void elements: مالهاش end tag

شوية elements مينفعش يبقى ليهم محتوى، فمالهمش end tag خالص: area base br col embed hr img input link meta source track wbr. ممكن تكتب <br> أو <br/> — الاتنين نفس الحاجة، والـ / في HTML ملهاش أي معنى (موجودة عشان التوافق مع XHTML بس).

الـ Attributes بالتفصيل

  • الأسماء case-insensitive في HTML: HREF = href (المتصفح بيحوّلها small). القيم غالبًا case-sensitive.
  • الـ quotes: double "…" أو single '…' أو من غير quotes لو القيمة مفيهاش مسافات ولا " ' = < > `. القيمة من غير quotes بتخلص عند أول مسافة — مصدر كلاسيكي للثغرات.
  • Boolean attributes (disabled، required، checked، hidden…): وجودها = true، أيًّا كانت القيمة. disabled="false" = disabled! عشان تلغيها لازم تشيل الـ attribute كله.
  • Attribute مكرر: الأول هو اللي بيكسب والتاني بيتشال (parse error). 🎯 لو فلتر بيتشيك على آخر واحد والمتصفح بياخد الأول — عندك bypass.

الـ Comments

الـ comments كنز recon

المسافات (whitespace)

المتصفح بيـدمج أي مجموعة مسافات/أسطر جديدة/tabs في النص لمسافة واحدة عند العرض. عشان كده الـ indentation في الكود مبيأثرش على الشكل. لو عايز سطر جديد: <br>، ولو عايز المسافات تفضل زي ما هي: <pre>، ولو عايز مسافة «مبتتكسرش»: &nbsp;.

HTML متسامحة… جدًا

لو كتبت Python غلط، هيطلع error ويقف. HTML لأ: الـ parser عنده قواعد مفصّلة لـ كل غلطة ممكنة، وبيكمّل ويطلع شجرة. ده كويس للمستخدم (الصفحة بتظهر)، بس معناه إن:

  • غلطاتك مش هتظهرلك لوحدها — استخدم W3C Validator (validator.w3.org) أو تاب Elements عشان تشوف الـ DOM الحقيقي.
  • 🎯 المتصفح بيفهم حاجات «غريبة» كـ HTML صحيح: tag من غير مسافة قبل الـ attribute، / مكان المسافة، attribute من غير quotes… فلتر بيدوّر على «الشكل المثالي» للـ HTML هيتعدّى.

تشغيل صفحاتك على جهازك
