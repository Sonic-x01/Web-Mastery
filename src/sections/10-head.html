الـ head: البيانات الوصفية وتحميل الموارد

الـ <head> مش بيظهر، بس هو «لوحة التحكم» بتاعة الصفحة: الـ encoding، الـ redirect، سياسة الـ Referer، الـ CSP، وترتيب تشغيل الـ scripts. وبالنسبة للـ recon، هو بطاقة الهوية: الـ CMS وإصداره، الـ frameworks، الخدمات الخارجية، وأحيانًا subdomains داخلية.

meta refresh في الـ phishing

إيميلات phishing كتير فيها مرفق HTML صغير جدًا مفيهوش غير <meta http-equiv="refresh" content="0;url=…"> — مفيش JavaScript خالص، فبعض الفلاتر بتعدّيه، والضحية بتتحوّل فورًا لصفحة المهاجم. ولو موقع شرعي عنده صفحة «redirect» بتحط URL من الـ query في meta refresh = open redirect على دومين موثوق يستخدمه المهاجم.

الـ Referrer Policy

تسريب الـ tokens في الـ Referer

  • <script type="module"> = deferred تلقائيًا، strict mode، وimport/export. وnomodule للمتصفحات القديمة.

Subresource Integrity (SRI): ثق في الملف مش في السيرفر

الـ integrity = hash للملف (الـ hash اللي فوق للتوضيح؛ بتحسبه بـ openssl dgst -sha384 -binary file.js | openssl base64 -A أو بتاخده من الـ CDN). المتصفح بيحسب الـ hash للي اتحمّل، ولو مختلف مبيشغّلوش. يعني لو الـ CDN اتخترق وغيّر الملف، صفحتك مش هتتأثر. الـ crossorigin="anonymous" لازم معاه للملفات من origin تاني.

🦠
Supply chain: polyfill.io (2024)

في 2024 دومين polyfill.io — اللي أكتر من 100 ألف موقع كانوا بيحمّلوا منه script — اتباع لجهة جديدة، وبدأ يبعت كود خبيث لبعض الزوار (redirects لمواقع مشبوهة، خصوصًا على الموبايل). المواقع اللي كانت حاطة SRI كانت هتبقى في أمان؛ لكن الخدمة دي بالذات كانت بترجع محتوى مختلف حسب المتصفح فمكنش ينفع يتعمله SRI أصلًا. الدرس: أي <script src> من دومين تالت = بتدّيه تحكم كامل في صفحتك. 🎯 في الـ recon: اعمل قايمة بكل الـ third-party scripts وشوف مين عليه SRI.

noscript وstyle

<noscript> محتواه بيظهر بس لو الـ JavaScript مقفول. 🎯 تفصيلة مهمة للأمن: الـ parser بيقرا محتوى noscript بطريقتين مختلفتين: لو الـ scripting شغّال = نص خام (RAWTEXT)، ولو مقفول = HTML عادي. الاختلاف ده استُخدم في bypasses حقيقية لـ sanitizers (الدرس 13). و<style> للـ CSS الـ inline، ومحتواه برضه RAWTEXT.

SRI = تحقق من hash المحتوى. مش تشفير ومش بيمنع XSS في كودك. صفحة `https://shop.example/reset?token=abc` فيها لينك لـ `https://cdn.partner.example/help` والـ policy هي الافتراضي. الـ Referer اللي هيوصل للـ partner؟ `https://shop.example/reset?token=abc` ولا حاجة `https://shop.example/` `/reset` الافتراضي `strict-origin-when-cross-origin`: cross-origin = origin بس. الـ token مش هيتسرّب… إلا لو حد غيّر الـ policy. الـ policy الافتراضية بتبعت الـ URL الكامل لنفس الـ origin بس، وللـ origins التانية الـ origin لوحده. أنهي directive مش بيشتغل لو الـ CSP اتحط في `` بدل header؟ `script-src` `frame-ancestors` `default-src` `img-src` `frame-ancestors` (وكمان `report-uri` و`sandbox`) لازم ييجوا من header. عشان كده حماية الـ clickjacking لازم header. الـ meta CSP بيدعم أغلب الـ directives، ماعدا `frame-ancestors` و`report-uri` و`sandbox`. `` — الكود ده بيعمل إيه؟ بيتنفّذ كـ JavaScript بيعمل error مبيتنفّذش — مخزن بيانات بيقراه الـ JS بـ `JSON.parse(state.textContent)`، ومكشوف لأي حد يقرا الـ source بيتبعت للسيرفر الـ type غير المعروف كـ JS = data block. ممتاز للـ recon: state كامل للتطبيق. المتصفح بينفّذ بس الـ scripts اللي نوعها JavaScript أو module. الباقي داتا.
